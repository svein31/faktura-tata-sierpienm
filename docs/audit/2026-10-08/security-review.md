## Kontrole granic i rzeczy niesprawdzone

Przegląd obejmował moduły sesji/CSRF, dostęp do firmy i zespołu, API kluczy publicznych, szyfrowanie webhooków i sprawdzanie publicznych IPv4, importy kontrahentów i dokumentów, zgody, profil i eksport. Macierz tras oraz cały przebieg API są raportowane w głównym audycie. Oczekiwane 400/401/403/409/413/423/429 w testach ujemnych nie są awariami aplikacji; nieoczekiwane 500 wymagają poprawki.

Nie wykonano pełnego testu penetracyjnego infrastruktury Netlify/MongoDB/Stripe/MF, testu podatności typu zero-day ani próby wydobycia rzeczywistych danych. Zewnętrzni dostawcy SMTP/OCR/skanera/MF/Stripe są zastępowani kontrolowanymi atrapami lub blokowani. Ochrona antywirusowa wymaga skonfigurowanego skanera: kontrola sygnatur i aktywnej treści nie dowodzi, że plik jest wolny od złośliwego kodu.

Wymuszany CSP obecnie ogranicza osadzanie strony, obiekty, bazowy URL i formularze. Nie zapewnia ścisłej listy skryptów przeciw XSS. Wprowadzenie takiej listy wymaga osobnego mechanizmu hashów dla każdej strony SSG i nonce dla prywatnego renderowania, wraz z testami zgodności; dodanie `unsafe-inline` nie rozwiązuje tego problemu. Usunięcie niezbieranych raportów nie zmniejsza istniejących wymuszanych ograniczeń.

Starszych haseł bcrypt powyżej 72 bajtów nie można naprawić odtworzeniem utraconego sufiksu z hasha. Zachowano zgodność logowania istniejących kont do czasu ustawienia nowego hasła; wszystkie nowe hasła i resety odrzucają nieobsługiwaną długość. Historycznych logów starych linków z query string nie można usunąć zmianą aplikacji. Nowe linki nie przesyłają tokena w adresie HTTP.
